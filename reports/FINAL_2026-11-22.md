# Phone avatar & sticker generator: final state (2026-11-22)

This report sums up the i2i-sticker-avatar study: which model to ship for each use, how good each model is, what was tried, and what is still open.
- Every number comes from `results/` (detailed log: `README.md`).
- Metric code: `scripts/expr_eval.py`, `scripts/eval_quality.py` (v2 set), `scripts/sharp_ratio.py`, `scripts/eval_e1.py`.
- Single seed. Expression scores use 24 synthetic faces (95% CI about ±0.05). Likeness uses 400 synthetic v2 faces.

## 1. What to ship

| Use | Best model now | Status |
|---|---|---|
| **cartoon3d avatar + 22 sticker options** | **dl6g2 + decg2** (DreamLite 390M, 1 step, text-free option tokens) | ✅ Core ML ready: `release/2026-11-19_dl6g2_decg2/` (w8e16 412 MB recommended; fp16 786 MB) |
| Faster sticker sets, same quality | **hhB0** (dl6g2 family; the per-photo part is shared across options and the photo half is dropped in the per-option part) | ✅ trained and evaluated: 2.2× less compute per 20-sticker set. ❌ not yet exported to Core ML (two-part export) |
| Sticker cut-out without BiRefNet | **decA** (RGBA decoder: decg2 + an alpha channel) | ✅ validated: sticker IoU 0.959 vs BiRefNet, post-process pass rate 100%. ❌ not exported |
| **3 styles (cartoon3d + comic_line + chibi), one model** | **dl9 + dec8** (one UNet + one decoder; style = 32 tokens + per-style FiLM, about 120 KB per style) | ✅ every style within noise of its specialist on expressions and likeness. ⚠️ comic sharpness 0.70 vs 0.83. ❌ not exported |
| 3 styles, best quality per style (more files) | cartoon3d **dl6g2 + decg2**; comic **pk_comic + decCm** (mid+up0 LoRA about 26 MB fp16 + decoder 2.5 MB); chibi **dl9 + dec8** (beats its pack) or pk_chibi + decg2 | ✅ evaluated. ❌ packs not exported |

**Recommendation:**
- **Ship cartoon3d today:** dl6g2 + decg2 (w8e16). Move to the hhB0 + decA build once it is exported and timed on an iPhone.
- **Multi-style: one model, dl9 + a decoder retrained on dl9 ("dec9").** This is simpler on the phone: one UNet + one decoder, and the style is an input index.
- Before dec9 exists, comic is the only style where the pack route (pk_comic + decCm) is clearly better, and only for sharpness.

## 2. Numbers

### 2.1 Per style: specialists vs the one-model route
Columns:
- **Expr** = CLIP 20-way accuracy, all / face-only / outside-the-face (the split is defined in `scripts/eval_e1.py`).
- **Id top-5** = sticker identity retrieval.
- **Likeness** = SFace cosine, avatar / sticker.
- **Sharp** = student / teacher Laplacian variance.

| Style | Model | Expr all / face / outside | Id top-5 | Likeness | Sharp |
|---|---|---|---|---|---|
| cartoon3d | dl6g2 + decg2 (specialist, shipped) | 0.583 / 0.729 / 0.486 | 0.346 | .248 / .221 | 0.64 |
| cartoon3d | dl9 + dec8 | 0.573 / 0.755 / 0.451 | 0.335 | .241 / .215 | 0.62 |
| comic_line | pk_comic + decCm (specialist) | 0.546 / 0.609 / 0.503 | 0.706 | .478 / .390 | 0.83 |
| comic_line | dl9 + dec8 | 0.535 / 0.635 / 0.469 | 0.688 | .492 / .400 | 0.70 |
| chibi | pk_chibi + decg2 (specialist) | 0.581 / 0.719 / 0.490 | 0.192 | .192 / .164 | 0.60 |
| chibi | dl9 + dec8 | 0.604 / 0.729 / 0.521 | 0.200 | .189 / .169 | 0.74 |

Likeness is not comparable across styles: the comic look keeps more photo detail than cartoon3d or chibi.

### 2.2 cartoon3d speed / phone variants
- **hhB0**: detail 1.00 / 422 (dl6g2 1.01 / 428); expression 0.552; sticker id top-5 0.377; likeness .242 / .163 / .184 (v2 / real / selfie); 2.2× less compute per 20-sticker set.
- **Core ML w8e16**: 35.9 dB PSNR vs fp16, LPIPS 0.006. Same speed, half the size (412 MB).
- **decA** (RGBA): RGB = decg2 (val LPIPS 0.2137 vs 0.2135). Alpha vs BiRefNet_lite: stickers IoU 0.959, avatars 0.995.

## 3. Tried and dropped (one line each; details in README)
- 2-step avatar refiner: −detail.
- Wider / deeper decoder: no gain.
- Cross-attention removal (dropX): −2 points expression for −5% compute per set.
- Pruned students pS70 / pS60: −18% / −31% likeness.
- Joint model dl7: −0.06 to −0.08 outside-face; fixed by dl8 → dl9.
- Tokens-only style pack: weaker.
- All-layer style pack: no better than mid+up0 at 2× the size.
- Wide latent (A): −detail.
- Skin drop-list (C, first attempt): no change.
- **Sana-Sprint 0.6B** (Apache-2.0 base): the student matches dl6g2 on expressions but has −41% likeness on the phone path (sC1). The cause is half the tiny DC-AE decoder (which itself stopped at step 10k because of a bug, since fixed) and half the student. Kept as the licence fallback (`weights/sana_student/sC1`).

## 4. Open issues / next steps
1. **dec9**: retrain the one decoder on dl9's latents (about 40 min GPU). Goal: comic sharpness from 0.70 toward 0.8.
2. **Comic "love" hearts** (0.00 vs pack 0.42) and faint raised hands: needs more gesture/heart data or a targeted loss.
3. **Dark-skin lightening** (all DreamLite students): real dark-skin photos are lightened by about +32 L* (klein +6.7). The root cause is in the teacher data. Not fixed.
4. **Core ML export** of hhB0 (two parts: shared trunk + per-option head), decA, and dl9 + dec8 (style index input). Then **iPhone timing** (owner, on device).
5. **Licence:** DreamLite weights are CC BY-NC 4.0, so legal must clear commercial use. Fallback: Sana-Sprint (Apache-2.0 + Gemma terms for the token init).
6. **Infra:** the h200-gpu-fleet host (gpu-h200-123) had a hung NVIDIA driver from 2026-11-21 ~07:50 UTC (another team's processes stuck in D state). Every dstack job there fails until a fleet admin resets it. dl9 was trained on the local H100.
